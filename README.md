# 小毛豆

一个适合情侣私人群聊的 QQ 机器人。平时安静待在群里，被 @ 时才会参与聊天。

## 可以做什么

- 陪你聊天、开启新话题
- 总结最近的聊天内容
- 看懂群里发的图片，包括聊天截图、照片和表情包
- 联网搜索资料、打开并总结网页（需要在 `.env` 填 `BOCHA_API_KEY`）
- 读取并解析 PDF、Word、Excel 和文本文件
- 计算数学表达式，或在受限沙箱里执行本地命令
- 帮忙润色想说的话
- 按日期或周期发送提醒和祝福：单次、每天、每周、每年（公历纪念日）、每年农历（农历生日）
- 重要日子可以「提前 N 天」再自动加一条预热提醒，当天那条照发
- 长期记忆只在你们明确让它记时才写：说「记住 xx」才入库，说「一定要记住」会置顶成 ★；日常闲聊只压成摘要当上下文，不会再自己往记忆里塞
- 说「先记一下、临时的」只保留 14 天，之后自动消失
- 回答「中秋是几号」「最近有什么节日」，农历公历互查
- 同一张图片只识别一次，重复发的表情包、课表不再二次调用视觉模型
- 情绪直接用 emoji 表达（😭😄🥲）。QQ 群消息不认表情标签，「[头秃]」这种写法发出去只是一对括号，所以出站前会被去掉
- 会发表情包：`assets/stickers/` 里 40 张动图 + 4 张小毛豆本尊（大耳帽兜），想发就把名字写进回复（「抱抱你呀[抱抱]」「[本尊委屈]」），群里收到的是真图；一条回复最多一张，图发不出去就退回纯文字
- 搜索、读文档这类慢操作超过 6 秒会先应一句“稍等我查一下”，不让人干等
- 只 @ 一下不说话，它顺着当前话题接一句，而不是每次都背一遍功能清单
- 办好一件事之后的那句确认话也带人设；编号、时间、称呼、条数照原样，说岔了就退回模板
- 没被 @ 时也能察觉「睡不好 / 累了 / 心情不好 / 肚子疼」，主动接一句 25 字以内的关心；长一点的倾诉（200 字以内）同样听得进去，拿不准就不说
- 群里说句话就能改它的行为，改完存在库里，优先级高于 `.env`

通过自然语言直接 @ 小毛豆即可，不需要记固定命令：

```text
@小毛豆 总结一下我们刚才聊了什么

@小毛豆 每年 12 月 13 日 09:00 提醒我们纪念日，提前 3 天先提个醒
@小毛豆 每年农历冬月初五 08:30 给她过生日
@小毛豆 记住她的真名叫小虾，一定要记住
@小毛豆 以后把「罗晓霞」和「小虾」都统一叫「二十四桥明月夜」
@小毛豆 以后叫我「主人」，叫他「小虾」
@小毛豆 你现在怎么称呼我们
@小毛豆 查看记忆
@小毛豆 第二页记忆
@小毛豆 中秋是几号
@小毛豆 以后别主动安慰我们
@小毛豆 看看群设置
@小毛豆 每人每天被关心次数改成 1
```

表情包的名字可以直接问它：@小毛豆 你有哪些表情包。

本尊那几张来自《洛克王国》游戏内形象，版权归腾讯，只在我们自己的私人群里用，别外传。

## 运行

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe main.py
```

也可以使用 Windows 后台脚本：

```powershell
.\scripts\start.ps1
.\scripts\status.ps1
.\scripts\stop.ps1
```

QQ 开放平台选择 WebSocket 连接，并开启接收群消息。

联网搜索使用博查（`BOCHA_API_KEY`），没有配置时机器人会明确说查不了，不会编造搜索结果。

农历换算依赖 `zhdate`（`requirements.txt` 已包含）；万一装不上，农历生日和节日查询会
回答「暂时算不出来」，其他功能不受影响。

## 部署

生产环境在 Linux 服务器上以 `xiaoxia.service` 运行，代码位于 `/opt/xiaoxia`。
本地改完 push 之后，一条命令完成部署：

```powershell
.\scripts\deploy.ps1 -DryRun   # 先看要做什么，不动服务器
.\scripts\deploy.ps1 -Force    # fetch -> 跑测试 -> 备份数据库 -> 重启 -> 健康检查
.\scripts\rollback.ps1         # 出问题退回上一个已部署版本
```

`deploy.ps1` 会先确认工作区干净且本地已 push；服务器上 `requirements.txt` 有变化才
`pip install`；测试不通过直接中止；健康检查失败自动回滚上一个版本。推送和回滚版本
记录在服务器的 `/var/lib/xiaoxia-deploy/`。

服务器在国内，偶尔会遇到 `api.github.com` 通、但 `github.com` 的 git 通道超时，远端
`git fetch origin` 拿不到新提交。为此 `deploy.ps1` 每次都会把同一分支的完整 bundle
一并传到 `/tmp/xiaoxia-deploy-bundle.bundle`：走 origin 正常时不会用到它，fetch 失败时
自动改从 bundle 补齐对象，日志里出现 `used offline bundle` 说明走了这条旁路。

GitHub Actions（`.github/workflows/ci.yml`）在每次 push 和 PR 上跑 `compileall` 和全部
单元测试，Python 3.11 / 3.12 各一次。

### 换群之后把记忆搬过去

记忆卡、称呼、叫法统一、群偏好、定时任务、对话摘要都以 `group_openid` 为键。QQ 换群或
重建群会拿到一个全新的 openid，机器人在新群里等于彻底失忆（「查看记忆」会回「我现在还没有
长期记忆」）。这时用 `scripts/migrate_group.py` 把旧群的数据搬过去：

```bash
cd /opt/xiaoxia
sudo -u xiaoxia .venv/bin/python scripts/migrate_group.py --db data/xiaoxia.sqlite3 --list
sudo -u xiaoxia .venv/bin/python scripts/migrate_group.py --db data/xiaoxia.sqlite3 \
    --from <旧群openid> --to <新群openid> --dry-run   # 先看清楚会搬多少
# 去掉 --dry-run 才真正写库，写库前自动留一份 .bak-migrate-<时间戳> 快照
```

只搬还活着的数据：已完成/已删除的任务不搬，聊天消息不搬（`message_key` 全局唯一，搬过去
只会撞键，新群的上下文从它自己的消息攒起），主动关心的节流账本不搬（免得白占新群额度）。
脚本可以重复执行，不会搬出重复条目；搬完不用重启服务，机器人每轮都是现查库。

## 隐私

聊天记录、图片描述和长期记忆保存在部署机器本地。机器人需要生成回复时，只会把完成任务所需的上下文发送给你配置的大模型服务。图片字节只在内存里用于识别和算内容指纹，落盘的是指纹加一段文字描述，原图不保存。`.env` 已被 `.gitignore` 忽略，密钥不要提交到 Git。
